决策因果链回溯过程

同一个贷款审批图,展示 trace_decision_chain() 与 analyze_decision_impact() 如何沿 CAUSED / INFLUENCED 边遍历

← 左:向上游回溯"这个利率决策是怎么来的" ｜ 右:向下游分析"承销决策影响了什么" →

向上游回溯 upstream

trace_decision_chain(rate, direction="upstream")
1
从 rate(利率决策)出发,沿 INFLUENCED 边逆向走到 underwriting (承销审批导致它)
2
继续沿 CAUSED 边逆向走到 credit_application (申请受理导致了承销)
3
到达根因,返回有序链 — 每步带 causal_distance(因果距离)
回溯结果:rate ← INFLUENCED ← underwriting ← CAUSED ← credit_application
回答"这个利率决策是怎么一步步来的"——这正是监管要的"why"

向下游影响 downstream

analyze_decision_impact(uw) # uw = 承销决策
1
从 underwriting 出发,沿 INFLUENCED 边正向遍历,找到下游 rate (承销影响了定价)
2
统计 total_influenced、计算每条下游的 影响分 (直接 + 间接)
3
返回影响图谱 — direct_influence / indirect_influence / max_score
影响结果:underwriting → 影响了 1 个直接下游(rate),总波及 2,最高影响分 0.45
回答"如果撤销承销决策,什么会受牵连"——风险传导分析
本质: 决策图谱一旦建成(节点 + 因果边),回溯/影响分析就是沿 CAUSED / INFLUENCED 边的有向图遍历——无需重跑推理,直接读图。 上游回溯(upstream)回答 "why"(监管审计),下游影响(downstream)回答 "what if"(风险传导)。 这正是《决策原生方法论》里决策轨迹与决策账本的工程体现:决策不仅被记录,还能被回放与波及分析。
